# Web Search Router

Определяет, какая из 8 канонических задач веб-поиска стоит перед агентом, и подбирает лучший инструмент. **Перед запуском дорогих режимов — останавливается и спрашивает разрешения.**

## Алгоритм работы

1. Прочитай запрос пользователя и сопоставь с **одной** из 8 задач ниже.
2. Если задач явно несколько — назови все и спроси, с какой начать.
3. Выбери основной инструмент из списка задачи. **Сначала из подключённых ✅, потом из неподключённых ⚙️.**
4. Если выбранный инструмент помечен **🛑 ДОРОГОЙ РЕЖИМ** — останови работу и пройди процедуру согласования (см. внизу).
5. Если задача неоднозначна (например, между #1 и #3) — задай 1-2 уточняющих вопроса перед запуском.

## Статус подключений (для этого пользователя)

Перед выбором инструмента сверься со списком — вызывать можно **только подключённые**.

✅ **Подключены и готовы к вызову:**
- Exa (MCP) — `web_search_exa`, `web_fetch_exa`
- Tavily (MCP) — `tavily_search`, `tavily_extract`, `tavily_crawl`, `tavily_map`, `tavily_research`
- Firecrawl (MCP) — `scrape`, `crawl`, `map`, `extract`, `interact`, `search`
- Parallel (MCP)
- Apify (MCP) — `Search Actors`, `Call Actor`, `Get Actor output`, и др.
- AnySite (MCP) — `discover`, `execute`, `get_page`, `query_cache`, `export_data`
- Brave Search (MCP) — `brave_web_search`, `brave_local_search`
- Claude Native Web Access — встроенный `WebSearch` / `WebFetch`

⚙️ **Не подключены (упомянуты в задачах для полноты, требуют отдельной настройки):**
- Perplexity Sonar API — нужен MCP + аккаунт ($50 минимум)
- NewsCatcher API — нужен MCP + платная подписка (~$250/мес минимум)
- Serper API — нужен MCP + аккаунт (бесплатные 2500 запросов)
- Jina AI Reader — можно без ключа

Если задача требует одного из ⚙️ как первого выбора — предложи пользователю либо подключить (одна команда), либо использовать ближайший подключённый аналог.

## AnySite vs Apify — общее правило

Эти два инструмента активны в задачах #4, #5, #6, #7, #8 — выбор между ними одинаковый везде:

- **AnySite** — узкий и быстрый. Берёшь, если нужный источник есть в их списке готовых эндпоинтов (Telegram-каналы — основной кейс). Указал источник → получил чистые данные. Без настройки скрейпера.
- **Apify** — широкий и гибкий. Берёшь, если AnySite не покрывает источник, или нужны соцсети (Instagram/TikTok/X/LinkedIn), Google Maps, маркетплейсы (Amazon/eBay), Indeed, Crunchbase, любые сайты без открытого API, большие/регулярные задачи. Минус — платится за каждый запуск, нужно выбрать правильный actor.

**Если непонятно покрыт ли источник AnySite** — сначала спроси пользователя или вызови `discover` в AnySite MCP. Если источника нет — переключайся на Apify.

## 8 задач

### 1. Найти информацию по смыслу (семантический поиск)

**Сигналы:** запрос — это идея/концепция/тип контента/тематика. Точных ключевых слов нет. Примеры: «блоги инженеров которые объясняют ML интуитивно», «эссе критикующие современные AI-бенчмарки».

**Инструменты:**
- **Exa** (MCP + API) — *первый выбор*. Единственный с настоящим семантическим поиском. Запрос формулируй как описание идеального контента, а не ключевые слова.
- **Parallel** API — тоже понимает смысл через `objective`, но избыточен для одного быстрого поиска (заточен под deep research).
- **Claude Native Web Access** — встроенный `web_search`, под капотом Brave (keyword), семантика базовая.

---

### 2. Найти информацию по точному запросу (keyword)

**Сигналы:** известны конкретные слова — название, бренд, дата, продукт, акроним. Примеры: «Anthropic Claude API pricing 2026», «Bing Search API shutdown date».

**Инструменты:**
- **Tavily** (MCP + API) — *первый выбор*. Google под капотом, один вызов = чистый текст без доп. шагов.
- **Brave Search API** — независимый индекс, без AI-обработки.
- **Serper API** — самый дешёвый доступ к Google-выдаче (только ссылки, без текста).
- **Perplexity Sonar API** — ищет и сразу формулирует готовый ответ со ссылками. Самый быстрый.
- **Claude Native Web Access** — встроенный `web_search` в Claude.ai и API.

---

### 3. 🛑 Провести глубокое исследование — ДОРОГИЕ РЕЖИМЫ ВНУТРИ

**Сигналы:** многоступенчатый вопрос, нужен синтез из 20-100+ источников, верификация утверждений, цитаты, сравнение позиций. Примеры: «сравни рынки X и Y», «исследуй индустрию Z», «глубокий анализ компании N».

**Инструменты:**
- **🛑 Parallel** (MCP + API) — ДОРОГОЙ РЕЖИМ. Лучший результат на сложных задачах (BrowseComp: 58%). 5-45 минут, много токенов. Сценарий запуска: `claude code + MCP Parallel`.
- **🛑 Exa `/research` endpoint** — ДОРОГОЙ РЕЖИМ. Автономный deep research, слабее Parallel на сложных задачах, но дешевле Parallel.
- **Perplexity Sonar API** — самый быстрый deep research (3-5 мин), огромный собственный индекс (200B+ URL). Дешевле Parallel/Exa research, но всё ещё стоит.
- **Claude Native Web Access (Claude Research)** — работает на этом механизме, 5-15 мин.

**Дешёвая альтернатива:** разбить руками на серию обычных поисков через Tavily/Exa search + чтение ключевых страниц через Exa fetch / Firecrawl scrape. Дольше по времени работы агента, но в разы дешевле.

---

### 4. Получить актуальные события (свежие, часы/дни)

**Сигналы:** мониторинг темы, breaking news, реакция на событие, сбор новостей за период. Примеры: «что написали про X сегодня», «последние анонсы за неделю», «вышел ли уже релиз Z».

**Инструменты:**
- **Tavily** (MCP + API) — *первый выбор*. Google под капотом, лучшее покрытие свежих новостей. Параметр `days` для фильтра.
- **NewsCatcher API** — единственный, чьё USP — доставка в минуты после публикации. 140k+ источников, near real-time стриминг. Не отвечает на запрос, а мониторит и стримит.
- **Exa API с livecrawl** — читает страницу прямо сейчас, минуя индекс. Нужен если контент опубликован буквально только что.
- **AnySite** (MCP) — *первый выбор для Telegram-каналов* (готовые эндпоинты под ProductsAndStartups, etonailya и т.п.). Также подходит для других поддерживаемых источников.
- **Apify** (MCP) — *первый выбор для соцсетей*: Instagram, TikTok, X, LinkedIn, Reddit. Готовые actors под каждую платформу. ⚠️ платится за каждый запуск.
- **Brave Search API** — фильтр свежести (день/неделя/месяц).
- **Perplexity Sonar API** — фильтр `search_recency_filter`, очень быстрый ответ (~358 мс).
- **Claude Native Web Access** — встроенный `web_search`.

---

### 5. Прочитать конкретную страницу (URL → текст)

**Сигналы:** URL уже известен. Поиск не нужен — нужен чистый текст страницы для обработки. Примеры: «прочитай эту статью», «извлеки текст из этого PDF», «получи содержимое этой документации».

**Инструменты:**
- **Exa** (MCP + API) — `web_fetch_exa` читает URL и возвращает чистый markdown.
- **Tavily** (MCP + API) — `tavily_extract` читает до 20 URL за один вызов (батч).
- **Firecrawl** (MCP + API) — *лучший выбор для JS-heavy страниц* (React/Vue/Angular). Где другие получают пустую страницу — Firecrawl получает полный контент.
- **AnySite** (MCP) — если страница из их списка готовых источников (быстрее: указал источник → получил чистые данные, без настройки скрейпера). `get_page` / `query_cache`.
- **Apify** (MCP) — Web Scraper / Cheerio / Puppeteer Scraper actors. Бери когда сайт со сложной антибот-защитой и нужен полноценный браузер с прокси. ⚠️ платится за каждый запуск.
- **Jina AI Reader** — бесплатно для базового использования, просто добавь URL к адресу.

---

### 6. Обойти весь сайт (crawling)

**Сигналы:** нужен не одна страница, а весь корпус сайта/раздела. URL отдельных страниц неизвестны. Примеры: «проиндексируй всю документацию», «собери все статьи блога», «получи все страницы продукта».

**Инструменты:**
- **Firecrawl** (MCP + API) — *первый выбор*. Самый надёжный, тянет JS-страницы.
- **Apify** (MCP) — *первый выбор для регулярного/большого крауления* (Trend Analyzer и т.п.). Готовые actors: Web Scraper, Website Content Crawler, плюс сайт-специфичные. Поддержка прокси, расписаний, мониторинга. ⚠️ платится за каждый запуск.
- **Tavily** (MCP + API) — `tavily_crawl` тоже умеет, но слабее на JS-страницах.

---

### 7. Взаимодействовать со страницей (browser automation)

**Сигналы:** нужно кликнуть, заполнить форму, прокрутить, нажать кнопку, пройти multi-step wizard. Контент доступен только после действия.

**Инструменты:**
- **Firecrawl** (MCP + API) — единственный из списка с инструментом `interact`: клики, формы, навигация как человек.
- **Apify** (MCP) — actors на Puppeteer/Playwright со встроенной поддержкой прокси, антибот-обхода, CAPTCHA-решения. Лучший выбор когда сайт активно детектирует автоматизацию. ⚠️ платится за каждый запуск.
- **Claude Native Web Access** — Claude Code + Playwright/Selenium: агент сам пишет код с headless-браузером.

---

### 8. 🛑 Собрать структурированный список объектов — ДОРОГИЕ РЕЖИМЫ ВНУТРИ

**Сигналы:** массовый сбор однородных данных, построение датасета. Примеры: «найди все компании которые используют LLM для медицины», «список всех выступлений Сэма Альтмана в 2025», «все статьи о vector databases за последний квартал».

**Инструменты:**
- **🛑 Exa Websets API** — ДОРОГОЙ РЕЖИМ. Специально создан для этой задачи: находит объекты по критериям и возвращает таблицу с заданными полями. Платится за каждый найденный/обогащённый объект.
- **🛑 Parallel FindAll API** — ДОРОГОЙ РЕЖИМ. Аналог Websets на индексе Parallel. Трёхэтапный пайплайн: генерация кандидатов → проверка по критериям → обогащение полями. Дороже Websets за счёт трёх этапов.
- **Apify** (MCP) — *первый выбор для соцсетей, маркетплейсов, карт, любых сайтов без API*. Готовые actors под Instagram/TikTok/LinkedIn/X, Amazon/eBay, Google Maps/Yelp, Indeed, Crunchbase, недвижимость, авиабилеты. Возвращает структурированный JSON/CSV. ⚠️ платится за каждый запуск, но обычно дешевле Websets/FindAll. Алгоритм: `Search Actors` → `Fetch Actor details` → `Call Actor` → `Get Actor output`.
- **AnySite** (MCP) — *первый выбор для Telegram-каналов и быстрой выборки из их списка готовых источников*. Указал источник → получил чистые данные в JSON/CSV. Без настройки скрейпера. Минус: ограничен списком поддерживаемых источников.
- **Firecrawl `/extract`** — *дешёвая альтернатива*. Извлекает структурированные данные с **конкретных** страниц по JSON-схеме. Требует, чтобы агент сам нашёл список URL.
- **Tavily `extract + LLM`** — *дешёвая альтернатива*. Находит страницы и достаёт текст, структурирование делается отдельно через LLM.

**Кейсы из практики (прямое правило):**
| Кейс | Инструмент |
|---|---|
| Telegram-каналы (Media Digest Bot) | AnySite |
| Парсинг Instagram/LinkedIn | Apify |
| Google Maps (студии для Dance Class Finder) | Apify |
| Быстрая выборка по конкретному сайту из списка AnySite | AnySite |
| Большой регулярный скрейпинг (Trend Analyzer) | Apify |
| Универсальный сбор объектов «найди всех X по критериям Y» | 🛑 Exa Websets / Parallel FindAll |

## 🛑 Процедура согласования дорогих режимов

Перед запуском любого из:
- **Exa Websets API**
- **Exa `/research` endpoint**
- **Parallel FindAll API**
- **Parallel** Deep Research (через MCP)

**ЖЁСТКОЕ ПРАВИЛО:** Останови всю работу. Не вызывай инструмент. Не делай предварительных запросов. Сначала пройди процедуру ниже.

### Шаг 2 — что считать «явным ДА»

Согласием считается **только** одно из:
- ✅ Сообщение содержит фразу **«ДА, ЗАПУСКАЙ»** + имя инструмента (или его явный вариант: «запускай Websets», «давай Parallel deep research»)
- ✅ Прямой ответ «да, запускай дорогой режим» / «yes, run expensive mode»

**НЕ считается согласием** (продолжай ждать):
- ❌ Молчание / эмодзи / реакция
- ❌ «продолжай», «ок», «ага», «давай» — без упоминания дорогого режима или инструмента
- ❌ Предыдущие согласования на другие задачи (каждый запуск — **отдельное** согласие)
- ❌ Согласие в дочернем агенте (sub-agent) — нужно поднять вопрос на главного пользователя
- ❌ «да» сказанное больше 5 минут назад в другом контексте

### Шаг 3 — двойная проверка перед вызовом инструмента

Прямо перед `mcp__...__call_tool(...)` мысленно проверь:
1. Я вывел красный блок 🚨🚨🚨? *Если нет — выведи сейчас, не вызывай.*
2. Юзер ответил «ДА, ЗАПУСКАЙ <имя>» в **последнем** сообщении? *Если нет — не вызывай.*
3. Юзер ответил на уточняющие вопросы (объём, поля, глубина)? *Если нет — переспроси.*

Только если на все 3 ответ «да» — запускай.

### Шаг 4 — после запуска

Сразу же после вызова дорогого инструмента уведоми пользователя:
```
🟢 Запустил <имя> — <ожидаемая длительность>. Жду результат.
```

## Если задача не подходит ни под одну из 8

- Спроси пользователя, что именно нужно — есть ли конкретный URL, известны ли точные слова, нужен ли текст или таблица, важна ли свежесть.
- Не выбирай инструмент наугад.
